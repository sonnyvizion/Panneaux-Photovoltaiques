# Design Système Astro (scaffold + tokens + hero) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the Astro project in `site/` and implement the visual design
system defined in `design.md` (tokens, fonts, core components), proven out by
rebuilding the real hero section from the client's mockup as the first working
page.

**Architecture:** A new Astro 7 project lives in `site/` (the existing root
keeps its planning docs untouched). Design tokens are plain CSS custom
properties (no CSS framework — matches the project's "zero JS by default"
philosophy from `stack.md`). Circular Std is self-hosted manually (files
already provided in `font/`); Geist Mono comes from the `@fontsource/geist-mono`
package. Components are plain `.astro` files with scoped `<style>` blocks; the
one piece of real logic (nav glass/opaque toggle) is a pure function unit-tested
with Vitest and wired via a small inline script (an "island" of JS, per
`stack.md`). No Sanity, no i18n routing, no simulator logic in this plan —
those are separate subsystems tracked elsewhere (`architecture.md`,
`simulateur.md`, `pages-contenu.md`).

**Tech Stack:** Astro 7 (minimal template, TypeScript strict), Node >= 22.12.0,
`@fontsource/geist-mono`, Vitest (one unit test only), native `<details>`/`<summary>`
for the accordion (zero JS).
